## Итоговая проверка проекта

| Требование | Проверка |
| --- | --- |
| Сбор, хранение и журнал | Два успешных ответа с одинаковым содержимым сохраняют одну копию на источник. Изменившийся ответ с той же меткой времени сохраняется отдельно. Каждая попытка отражается в журнале. В повторном реальном запросе «Таёжный» дал ноль новых порций. При недоступности онлайн-афиши сработал локальный архив |
| Витрина признаков | Единая функция строит признаки для обучения и прогноза. Тест проверяет влияние будущих фактов. В отчёте описаны причины индикаторного кодирования и сравнение с исключением блока афиши |
| Модели и воспроизводимость | 24 теста прошли. На чистой базе повторная архивная сборка дала ноль новых порций, все 26 экспериментов воспроизвелись по ID. Метрики и прогнозы совпали с контрольным выпуском |
| Дашборд и интерпретация | В Edge прошли проверки фильтров, таблиц, графиков, CSV и мобильной ширины. `/health` и `/api/data` проверены на отдельном локальном сервере |
| Проверка Ridge | Итоговый JSON на исходном архиве реальных бронирований воспроизвёлся побайтно. Результаты относятся к ADR двух отелей Португалии |
| Отчёт и презентация | В отчёте описаны источники, модели, результаты и ограничения. На третьем слайде обоснованы Python, NumPy, SQLite и браузерный интерфейс. |
